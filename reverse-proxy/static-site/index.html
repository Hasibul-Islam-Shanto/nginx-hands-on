Core Capabilities

Why engineers worldwide make NGINX their first choice for web infrastructure.

Reverse Proxying

Directs incoming client requests seamlessly to one or multiple backend upstream services, hiding your application servers from direct exposure and enhancing network security.

Load Balancing

Distributes traffic across pools of microservices using algorithms such as Round Robin, Least Connections, and IP Hash to maximize throughput and eliminate bottlenecks.

SSL/TLS Termination

Offloads computationally expensive cryptographic handshakes at the edge. Centralizes SSL certificate rotation, HTTP/2 & HTTP/3 multiplexing, and security headers.

Static Asset Caching

Leverages zero-copy Linux syscalls (sendfile) to deliver images, HTML, CSS, and JS bundles directly from disk cache to the network socket with near-zero CPU overhead.

DDoS & Rate Limiting

Built-in leaky bucket rate limiting zones, IP blacklisting, connection throttling, and request size filters protect your downstream infrastructure from abuse.

WebSocket & gRPC Support

Effortlessly manages long-lived bidirectional WebSocket tunnels and multiplexed HTTP/2 gRPC microservice communication channels without connection drops.

The Event-Driven Advantage

Unlike traditional process-per-request or thread-per-request servers (such as classic Apache MPM), NGINX was designed from ground up with an asynchronous, non-blocking event-driven loop.

NGINX (Event-Driven) High Efficiency
  • Single Master Process manages worker processes
  • Workers run a single-threaded asynchronous epoll/kqueue loop
  • Handles 10,000+ concurrent requests per worker
  • Constant low memory consumption under heavy load
  • No costly OS thread context switching overhead
Traditional Servers (Threaded)
  • Allocates a new dedicated process/thread per request
  • Significant RAM consumed per open connection
  • Degrades rapidly when hit with concurrency spikes
  • Heavy kernel context switching penalties

Sample Reverse Proxy Configuration

A typical production snippet routing requests to static files and backend servers.

/etc/nginx/conf.d/default.conf
upstream backend_cluster {
    server 127.0.0.1:3000;
    server 127.0.0.1:3001;
    keepalive 32;
}

server {
    listen 80;
    server_name example.com www.example.com;

    # Serve Static Website Files
    location / {
        root /var/www/static-site;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # Reverse Proxy API Traffic to Backend Cluster
    location /api/ {
        proxy_pass http://backend_cluster;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

Quick CLI Cheatsheet

Standard commands to manage and reload your NGINX daemon.

nginx -t
Test configuration syntax for errors before reloading.
nginx -s reload
Hot-reload config with zero dropped connections or downtime.
brew services start nginx
Start NGINX as a background service via Homebrew.
nginx -s quit
Graceful shutdown allowing active connections to complete.
